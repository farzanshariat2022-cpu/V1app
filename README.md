# معمار (The Architect) — فازهای ۱ تا ۳ + رفع مشکل بیلد Codemagic

این نسخه شامل: احراز هویت، داشبورد با DailyBriefing واقعی (تولید سمت کلاینت)،
سیستم هدف درختی (Goal → Project → Milestone → Week → Day → Task)، و Skill Tree
کامل با ۴ دسته و منطق لول‌آپ است. فازهای بعدی (عادت‌ها، ژورنال هوشمند، ضد
اهمال‌کاری و...) روی همین پایه اضافه می‌شوند.

**آپدیت مهم:** روش تامین `google-services.json` برای بیلد Codemagic از حالت
Environment Variable (شکننده) به حالت **فایل مستقیم داخل ریپو** تغییر کرد. اگر
قبلاً این پروژه را داشتی، فقط کافی‌ست بخش «قرار دادن google-services.json» در
پایین را دوباره بخوانی و `codemagic.yaml` جدید را جایگزین کنی.

## ⚠️ نکته مهم درباره‌ی پوشه android/

چون این پروژه بدون نصب Flutter روی سیستم من ساخته شده، پوشه‌ی استاندارد `android/`
(که معمولاً با دستور `flutter create` تولید می‌شود) در این پکیج **وجود ندارد**.
این تصمیم عمدی است: تولید `android/` توسط خود Flutter در سرور Codemagic تضمین
می‌کند که فایل‌های حساسی مثل Gradle Wrapper (که به‌صورت باینری و وابسته به نسخه‌ی
دقیق Flutter/Gradle هستند) همیشه معتبر و به‌روز باشند — دست‌ساز کردن آن‌ها بدون
اجرای واقعی Flutter می‌توانست بیلد را به‌شکلی نامعتبر و غیرقابل‌دیباگ خراب کند.
تنها بخشی که واقعاً نیاز به کنترل داشت (تنظیمات Firebase در Gradle) از طریق
پوشه‌ی `ci/` و فایل `firebase/google-services.json` مدیریت می‌شود که هر دو در
همین ریپو کامیت شده‌اند و در بیلد جایگزین می‌شوند. پس نگران نباش — نیازی به نصب
Flutter روی لپ‌تاپت نیست و بعد از اضافه‌کردن فایل واقعی فایربیس (پایین توضیح
داده شده)، هر بار که پروژه را به Codemagic بدهی، بدون هیچ تنظیم دستی اضافه‌ای
بیلد می‌شود.

## مراحل راه‌اندازی (قبل از آپلود به Codemagic)

### ۱. ساخت پروژه Firebase

۱. برو به [console.firebase.google.com](https://console.firebase.google.com) و یک پروژه جدید بساز (مثلاً `architect-app`).
۲. داخل پروژه، یک اپ Android اضافه کن با **Package name دقیقاً برابر**:
   ```
   com.farzan.architect
   ```
   (اگر می‌خواهی اسم دیگری بگذاری، هم اینجا و هم در `ci/android_app_build.gradle`
   مقدار `applicationId` و `namespace` را همزمان عوض کن — بیلد اگر این دو یکی
   نباشند، خودش با یک پیام خطای واضح متوقف می‌شود، پس اشتباه بی‌سروصدا رد نمی‌شود.)
۳. فایل `google-services.json` را دانلود کن.
۴. در Firebase Console:
   - **Authentication → Sign-in method → Email/Password** را فعال کن.
   - **Firestore Database** را بساز (Start in production mode کافی است، چون فایل
     `firestore/firestore.rules` قوانین امن را برایت نوشته).
   - محتوای `firestore/firestore.rules` را در تب **Rules** پیست و Publish کن.

### ۲. قرار دادن google-services.json (روش نهایی و پایدار)

فایل دانلودشده را **دقیقاً** جایگزین این مسیر داخل ریپو کن:
```
firebase/google-services.json
```
(الان همان‌جا یک فایل نمونه/الگو به اسم `firebase/google-services.json.example`
هست تا ساختار را ببینی — فایل واقعی‌ات باید اسمش دقیقاً `google-services.json`
باشد، بدون `.example`.)

این فایل **محرمانه نیست** (خود مستندات رسمی فایربیس هم همین را می‌گوید — امنیت
واقعی از طریق Firestore Security Rules تامین می‌شود، نه پنهان‌کردن این فایل)،
پس مشکلی ندارد که مستقیم داخل ریپو کامیتش کنی.

**چرا این روش به‌جای Environment Variable در Codemagic؟**
چون در UI فعلی Codemagic امکان آپلود فایل وجود ندارد و فقط متغیرهای متنی
(plain/base64) پشتیبانی می‌شود — که برای محتوای JSON چندخطی مستعد خطای کپی/پیست
و انکودینگ است. با کامیت‌کردن فایل مستقیم در ریپو، این لایه‌ی شکننده کاملاً حذف
می‌شود: `codemagic.yaml` فقط این فایل را از مسیر `firebase/google-services.json`
داخل همان android که در زمان بیلد ساخته می‌شود کپی می‌کند — بدون نیاز به هیچ
تنظیم اضافه در پنل Codemagic. اگر این فایل را (با محتوای واقعی) در ریپو نگذاری،
بیلد از همان مرحله‌ی اول با یک پیام فارسی واضح متوقف می‌شود، نه با خطای گنگ
Gradle در انتهای بیلد.

### ۳. آپلود در Codemagic

۱. پروژه را به‌صورت زیپ یا از طریق یک ریپوی Git (GitHub/GitLab/Bitbucket) به Codemagic بده.
۲. Codemagic باید فایل `codemagic.yaml` را خودش شناسایی کند (workflow با نام
   `architect-android`). هیچ Environment Variable Group ای لازم نیست.
۳. بیلد را اجرا کن. خروجی، فایل APK نصبی زیر مسیر
   `build/app/outputs/flutter-apk/app-release.apk` خواهد بود که Codemagic
   به‌صورت artifact قابل دانلود نمایش می‌دهد.

## ساختار داده Firestore (فاز ۱)

```
users/{uid}
  email, displayName, createdAt, xpRates

users/{uid}/daily_logs/{yyyy-MM-dd}
  studyMinutes, workoutMinutes, totalScreenTimeMinutes,
  instagramMinutes, youtubeMinutes, sleepHours, moodScore,
  xpEarned, journalWritten

users/{uid}/screen_time/{yyyy-MM-dd}
  totalScreenTimeMinutes, instagramMinutes, youtubeMinutes, lastUpdated
```

این ساختار عیناً همان چیزی است که در بخش ۱ پرامپت اصلی توضیح داده شده، تا Cloud
Function تحلیل شبانه در فاز بعد بدون تغییر ساختار داده روی همین بنا شود.

## فاز ۲ — سیستم هدف + DailyBriefing واقعی

### ⚠️ چرا بدون Cloud Functions؟
طبق بررسی دقیق، **Cloud Functions حتی در حجم مصرف رایگان هم نیاز به فعال‌سازی پلن
Blaze (پرداخت به‌ازای مصرف + کارت بانکی) دارد** — این محدودیتی از طرف گوگل است و
هیچ راه دوری ندارد. چون خواسته بودی کاملاً روی Spark Plan بمانیم، منطق
`analyzeDayAndPlanTomorrow` را **داخل خود اپ فلاتر** پیاده کردم: هر بار اپ باز
می‌شود، اگر بریفینگ امروز هنوز ساخته نشده باشد، داده‌ی دیروز را با میانگین ۷ روز
قبل‌تر مقایسه می‌کند، علت ریشه‌ای را حدس می‌زند، و متن انگیزشی می‌سازد — دقیقا
همان منطق Cloud Function توضیح‌داده‌شده در پرامپت، فقط اجراکننده‌اش کلاینت است
نه سرور. یک دکمه‌ی 🔄 «تحلیل مجدد» هم روی کارت گذاشته‌ام تا هر وقت خواستی
دستی دوباره تولیدش کنی.

### فعال‌سازی هوش مصنوعی واقعی (Gemini)
۱. به [aistudio.google.com/apikey](https://aistudio.google.com/apikey) برو و یک
   کلید رایگان Gemini بساز (کارت بانکی لازم نیست، این سرویس جدا از Firebase است).
۲. داخل اپ روی آیکون ⚙️ در بالای داشبورد بزن و کلید را وارد کن.
۳. اگر کلید را وارد نکنی، اپ همچنان کار می‌کند اما به‌جای متن تولیدشده توسط
   Gemini، یک تحلیل قالبی (بدون AI ولی مبتنی بر همان اعداد واقعی‌ات) نشان می‌دهد.

### سیستم هدف (Goal Hierarchy)
تب «اهداف» در نوار پایین اضافه شده. ساختار درختی دقیقا طبق بخش ۲ پرامپت:
هدف اصلی ← پروژه ← نقطه عطف ← هفته ← روز، و تسک در هر سطحی قابل افزودن است.
از منوی سه‌نقطه‌ی کنار هر گره می‌توانی زیرمجموعه/تسک اضافه کنی، ویرایش کنی، یا
با تایید، آن گره و تمام زیرمجموعه‌ها/تسک‌هایش را حذف کنی (حذف آبشاری).
تیک‌زدن یک تسک، XP آن را خودکار به `xpEarned` لاگ امروز اضافه می‌کند.

## فاز ۳ — XP و Skill Tree

تب سوم «مهارت‌ها» به نوار پایین اضافه شد، با ۴ زیرتب دقیقا طبق بخش ۳ پرامپت:
**دانش، بدن، ذهن، روابط**.

- هنگام ثبت‌نام، ۱۰ مهارت پیش‌فرض از لیست پرامپت خودکار ساخته می‌شود (مطالعه،
  ورزش، شطرنج، تخته‌نرد، زبان، طراحی، کتاب‌خوانی، پادکست، ژورنال‌نویسی،
  مدیتیشن) با همان نرخ‌های XP که خودت مشخص کرده بودی. دسته‌ی «روابط» عمداً
  خالی می‌ماند تا خودت مهارت‌های اجتماعی دلخواهت (مثلا «وقت با خانواده») را
  با دکمه‌ی + اضافه کنی.
- هر مهارت یک نرخ XP-به-ازای-واحد قابل‌ویرایش دارد (واحدش می‌تواند «دقیقه»،
  «بازی»، «روز» یا هرچیز دلخواه باشد) — پس هم می‌توانی مهارت‌های پیش‌فرض را
  دست بزنی، هم مهارت کاملا جدید با نرخ خودت بسازی.
- دکمه‌ی «ثبت فعالیت» روی هر کارت مهارت، مقدار فعالیت را می‌گیرد، XP را
  محاسبه می‌کند، و **در یک تراکنش امن Firestore** آن را به XP/لول مهارت اضافه
  می‌کند. وقتی XP به آستانه‌ی `۱۰۰ × لول فعلی` برسد، خودکار لول‌آپ می‌شود و یک
  اسنک‌بار جشن (🎉) نشان داده می‌شود.
- هنگام ساخت تسک در تب «اهداف»، حالا می‌توانی آن تسک را به یک مهارت وصل کنی؛
  با تیک‌زدن تسک، هم XP امروز و هم XP همان مهارت بالا می‌رود.

## فاز ۴ — ردیاب عادت (Habit Tracker)

تب چهارم «عادت‌ها» به نوار پایین اضافه شد، دقیقا طبق بخش ۴ پرامپت:

- هر عادت یک کارت دارد با: **استریک** (روزهای پشت‌سرهم 🔥)، **درصد موفقیت**
  (٪ از روز ساخت عادت تا امروز)، یک دکمه‌ی بزرگ «امروز انجام بده»، و یک
  **Heat Map مشابه گیت‌هاب** (`flutter_heatmap_calendar`) که هم روزهای موفق را
  سبز نشان می‌دهد و هم می‌توانی مستقیم روی هر خانه‌اش تپ کنی تا آن روز خاص را
  تیک بزنی/برداری (برای ثبت عقب‌افتاده هم به‌درد می‌خورد).
- اگر یک عادت **۳ روز پشت‌سرهم** انجام نشود، دور کارتش یک حاشیه‌ی قرمز و پیام
  هشدار ظاهر می‌شود؛ و — چون Cloud Function نداریم — همین هشدار به‌صورت خودکار
  به متن **DailyBriefing** روی داشبورد هم اضافه می‌شود (چه نسخه‌ی Gemini، چه
  نسخه‌ی قالبی بدون AI).
- استریک با منطق «اگر امروز هنوز ثبت نشده، از دیروز شمارش می‌شود» کار می‌کند
  (چون امروز هنوز تمام نشده)؛ به‌محض جاافتادن یک روز کامل، صفر می‌شود.

## فاز ۵ — ژورنال هوشمند

تب پنجم «ژورنال» اضافه شد، دقیقا طبق بخش ۵ پرامپت:

- یک ادیتور متن ساده بالای صفحه برای نوشتن آزاد.
- بعد از زدن «ذخیره و تحلیل»، متن فوراً ذخیره می‌شود (بدون معطلی) و تحلیل
  Gemini در پس‌زمینه اجرا می‌شود؛ کارت مربوطه تا وقتی تحلیل تمام نشده
  «در حال تحلیل...» نشان می‌دهد و خودش (چون به Firestore گوش می‌دهد) به‌محض
  آماده‌شدن نتیجه، سه چیز را نشان می‌دهد: **احساس غالب**، **موضوع اصلی**، و
  یک **توصیه کوتاه**.
- اگر کلید Gemini را در تنظیمات وارد نکرده باشی، به‌جای تحلیل هوشمند یک پیام
  راهنما نشان داده می‌شود، ولی خود نوشته‌ات همچنان ذخیره و قابل مرور است.
- طبق نرخ پیش‌فرض بخش ۳ پرامپت («نوشتن ژورنال: ۱۰ XP در روز»)، اولین نوشته‌ی
  هر روز ۱۰ XP به `xpEarned` همان روز اضافه می‌کند و `journalWritten` را
  `true` می‌کند (نوشته‌های بعدی همان روز XP اضافه نمی‌دهند تا این پاداش
  تکراری نشود).

## فاز ۶ — ضد اهمال‌کاری، تحلیل خواب/ورزش، Reward & Punishment

همه‌ی این سه سیستم (بخش‌های ۱۱، ۱۳، ۱۴ پرامپت) هم — طبق همون تصمیم فاز ۲ —
سمت کلاینت پیاده شدن، نه با Cloud Function زمان‌بندی‌شده:

### ضد اهمال‌کاری (بخش ۱۱)
اگه ۳ روز پشت‌سرهم هم مطالعه (<۳۰ دقیقه) و هم ورزش (<۱۰ دقیقه) کم بوده، یک
بنر قرمز روی داشبورد ظاهر می‌شه و بخش «کارهای در انتظار» خودکار فقط ۳ تسک
غیر-اختیاری رو نشون می‌ده (نه همه‌ی تسک‌ها رو) — دقیقاً همون «سبک‌کردن برنامه»
که در پرامپت خواسته شده بود، با این تفاوت که به‌جای حذف داده، فقط *نمایش* رو
فیلتر می‌کنه (چیزی از دست نمی‌ره). هنگام ساخت تسک در تب «اهداف» حالا یک
گزینه‌ی «اختیاری» هم هست که همین فیلتر ازش استفاده می‌کنه.

### تحلیل خواب و ورزش (بخش ۱۳)
- فرم «ثبت دستی امروز» حالا ساعت خواب، ساعت خوابیدن، ساعت بیداری، و
  خلق‌وخوی امروز (با ایموجی) رو هم می‌گیره.
- یک کارت «میانگین خواب هفته» روی داشبورد میانگین ساعت خواب ۷ روز اخیر و
  ساعت خواب/بیداری معمولت رو نشون می‌ده تا بتونی ثابت نگهش داری.
- آیکون 🏋️ کنار داشبورد یک صفحه‌ی «تحلیل ورزش» جدید باز می‌کنه: هر حرکت
  (مثلا «پرس سینه: ۳ ست ۱۰ تایی ۲۰ کیلو») رو لاگ می‌کنی و یک نمودار روند
  وزنه براش رسم می‌شه؛ اگه حدود ۲ هفته پیشرفتی نبوده (حجم تمرین کمتر یا
  مساوی نسبت به ۲ هفته قبل)، هشدار «شاید وقتشه برنامه رو عوض کنی» می‌بینی.

### Reward & Punishment (بخش ۱۴)
- **Reward:** اگه ۲۰ روز پشت‌سرهم حداقل کمی مطالعه کرده باشی، یک دستاورد
  «۲۰ روز مطالعه‌ی پشت‌سرهم 🔥» باز می‌شه و یک دیالوگ تبریک نشون داده می‌شه.
- **Punishment:** اگه همون شرط ۳-روزه‌ی رکود (بالا) برقرار باشه، ۲۰٪ از XP
  یک مهارت تصادفی کم می‌شه و یک دیالوگ هشدار نشونت می‌ده کدوم مهارت و چرا.
  برای اینکه در طول یک رکود طولانی هر روز دوباره تنبیه نشی، این کار حداکثر
  هر ۳ روز یک‌بار اجرا می‌شه.

## فاز ۷ (نهایی) — چت هوشمند، تصمیم‌گیری، مدیریت درس، پروژه، گزارش ماهانه، نوتیفیکیشن

این فاز آخرین فاز برنامه‌ریزی‌شده بود و ۶ سیستم باقی‌مانده‌ی پرامپت اصلی را
تکمیل می‌کند. همه‌چیز همچنان سمت کلاینت و روی Spark Plan محض کار می‌کند.

### 🐛 یک اصلاح مهم زیرساختی (قبل از هر چیز)
هنگام بازبینی دقیق، متوجه شدم چند کوئری در `FirestoreService` (فیلتر
equality + `orderBy` روی یک فیلد دیگر — مثلاً «فرزندان یک هدف را بگیر و بر
اساس ترتیب مرتب کن») در Firestore به یک **composite index** دستی نیاز
دارند. روی یک APK نصب‌شده (بدون دیباگر متصل)، این خطا هیچ‌جا نمایش داده
نمی‌شود — کاربر فقط یک لیست همیشه خالی می‌بیند، بدون هیچ توضیحی. برای حذف
کامل این ریسک، تمام این کوئری‌ها بازنویسی شدند تا فقط فیلتر روی Firestore
انجام شود و مرتب‌سازی (که برای حجم داده‌ی یک اپ شخصی کاملاً سبک است) سمت
کلاینت در Dart انجام شود. نتیجه: **هیچ‌کدام از کوئری‌های این اپ، در هیچ
شرایطی، نیاز به ساخت دستی ایندکس در Firebase Console ندارند.**

### چت هوش مصنوعی با حافظه (بخش ۱۲)
آیکون 💬 بالای داشبورد. دستیار به این‌ها همزمان دسترسی دارد: حافظه‌ی
بلندمدتی که خودت با آیکون 🧠 کنار چت اضافه می‌کنی (مثلا «سه‌شنبه‌ها از ۴ تا
۷ کلاس دارم»)، وضعیت امروزت (مطالعه/ورزش/گوشی/خلق‌وخو)، اهداف بلندمدتت، و
۱۰ پیام اخیر مکالمه — تا پاسخ‌هاش واقعاً به زندگیت مرتبط باشه، نه کلی‌گویی.

### سیستم تصمیم‌گیری (بخش ۷)
از منوی ⋮ روی داشبورد → «کمکم کن تصمیم بگیرم». دو گزینه رو وارد می‌کنی، با
دسترسی به اهداف بلندمدتت یک تحلیل هزینه-فایده‌ی کوتاه می‌گیری.

### مدیریت درس با مرور علمی (بخش ۹)
از منوی ⋮ → «درس‌ها». ساختار درس ← فصل ← مبحث. با تیک‌زدن یک مبحث به
«تکمیل‌شده»، خودکار ۵ تسک مرور برای ۱، ۳، ۷، ۱۵ و ۳۰ روز بعد ساخته می‌شود
(دقیقاً الگوریتم گفته‌شده در پرامپت). هر درس یک نوار «X از Y مبحث تکمیل» و
شمارش معکوس تا امتحان دارد.

### مدیریت پروژه (بخش ۱۰)
به‌جای یک سیستم جداگانه، این قابلیت مستقیم به همون تب «اهداف» اضافه شد: حالا
موقع ساخت گره ریشه می‌تونی «پروژه مستقل» انتخاب کنی (نه فقط «هدف اصلی»)، و
هر گره‌ی نوع پروژه یک اسلایدر پیشرفت ۰ تا ۱۰۰٪ داره که به‌صورت نوار پیشرفت
زیر عنوانش نمایش داده می‌شه — دقیقاً مثال «طراحی UI: ۷۰٪» در پرامپت.

### گزارش شخصیت ماهانه (بخش ۶)
از منوی ⋮ → «گزارش ماهانه». دکمه‌ی «ساخت گزارش این ماه» تمام لاگ‌های همون
ماه رو می‌خونه: میانگین خلق‌وخو، مجموع مطالعه/ورزش، و همبستگی ساده‌ی
اینستاگرام-بالا/مطالعه-پایین (به‌عنوان بیشترین علت اهمال‌کاری) رو حساب
می‌کنه و با Gemini (یا بدون اون، با یک متن قالبی مبتنی بر همون اعداد) یک
تحلیل کوتاه می‌سازه.

### یادآور هوشمند (بخش ۱۵)
- نوتیفیکیشن ساعت ۷ صبح و ۱۰ شب هر روز خودکار زمان‌بندی می‌شود (`flutter_local_notifications`).
- زیرساخت یادآوری ۵ دقیقه قبل از تسک‌های زمان‌دار هم آماده است
  (`NotificationService.scheduleTaskReminder`)، برای فازهای بعدی که بخوای
  زمان دقیق به تسک‌ها اضافه کنی.
- **تصمیم فنی:** به‌جای حالت Exact Alarm (که روی اندروید ۱۲+ نیاز به مجوز
  ویژه و رفت‌وبرگشت با تنظیمات سیستم داره)، از حالت inexact استفاده شده —
  نوتیفیکیشن ممکنه تا ~۱۵ دقیقه دیرتر برسه، ولی بدون نیاز به مجوز خاص روی
  همه‌ی گوشی‌ها قابل‌اعتماد کار می‌کنه.
- برای این‌که این مجوزها/گیرنده‌ها در بیلد واقعی وجود داشته باشن، یک
  `ci/AndroidManifest.xml` سفارشی اضافه شد که `codemagic.yaml` بعد از
  `flutter create`، درست مثل فایل‌های gradle، جایگزینش می‌کنه.

## وضعیت نهایی

با فاز ۷، هر ۱۵ بخش پرامپت اصلی پیاده‌سازی شده. این پیشنهادهای اختیاری برای
آینده هستن (هیچ‌کدام برای کارکردن اپ ضروری نیستن):

- **ردیابی زنده‌ی اسکرین‌تایم** با پکیج `usage_stats` (فعلاً ورودی دستی
  اسکرین‌تایم از طریق فرم داشبورد انجام می‌شه؛ اتصال مستقیم به Android Usage
  Stats API نیاز به یک صفحه‌ی درخواست مجوز ویژه‌ی اندروید داره).
- **زمان دقیق برای تسک‌ها** (تا از `NotificationService.scheduleTaskReminder`
  که از قبل آماده‌ست استفاده بشه).
- **گزارش ماهانه به‌صورت PDF** قابل‌دانلود (فعلاً فقط داخل خود اپ نمایش داده
  می‌شه؛ برای فایل PDF واقعی به پکیج‌های `pdf`/`printing` نیاز داره).
- **Google Fit API** برای خواندن خودکار داده‌ی خواب به‌جای ورود دستی.

## ساختار کامل نهایی پروژه

```
lib/
  main.dart                          # راه‌اندازی Firebase + نوتیفیکیشن
  models/                            # ۱۶ مدل داده (User, DailyLog, Goal, Task,
                                      # Skill, Habit, Journal, Briefing, Workout,
                                      # Achievement, Course, Chapter, Topic,
                                      # ChatMessage, MemoryItem, MonthlyReport)
  services/                          # منطق کسب‌وکار: Auth, Firestore, Gemini,
                                      # DailyAnalysis, Gamification, Chat,
                                      # Decision, MonthlyReport, Notification
  screens/
    auth/                            # ورود، ثبت‌نام
    dashboard/                       # داشبورد اصلی + فرم ورود دستی
    goals/                           # درخت هدف/پروژه/تسک
    skills/                         # Skill Tree
    habits/                          # ردیاب عادت + Heat Map
    journal/                         # ژورنال هوشمند
    workout/                         # لاگ ورزش + نمودار روند
    courses/                         # مدیریت درس + مرور علمی
    chat/                            # چت هوش مصنوعی + مدیریت حافظه
    decision/                        # سیستم تصمیم‌گیری
    reports/                         # گزارش ماهانه
    settings/                        # کلید Gemini
    home/                            # HomeShell (نوار پایین)
  widgets/, theme/                   # اجزای مشترک UI
firebase/google-services.json        # پیکربندی فایربیس (باید خودت جایگزین کنی)
firestore/firestore.rules            # قوانین امنیتی
ci/                                  # فایل‌های gradle + AndroidManifest برای CI
codemagic.yaml                       # پیکربندی بیلد خودکار APK
```

هر فاز را در یک پیام جدا از من بخواه تا کامل و تست‌شده تحویل بدهم؛ در یک پیام
واحد بیلد کردن کل ۱۵ بخش عملاً قابل کنترل کیفی نیست.
